1. Executive Summary & Problem Scope

The Campus Emergency & Smart Patient Triage System provides an enterprise-grade emergency response command platform designed specifically for university and institutional environments. The system bridges the critical time gap between incident occurrence and professional intervention by unifying two vital domains:

  • Tactical SOS Reporting (Caller Domain): One-tap panic triggers, rich symptom reporting, and zero-delay bystander guidance.
  • Smart Patient Triage Engine (Clinical Domain): Automated keyword heuristics, risk-factor age escalation, unit dispatch assignments, and localized facility routing.
  • Incident Telemetry Command Center (Admin Domain): Real-time situational awareness, audio siren alerts, priority filtering, and ticket status progression (Dispatched → En Route → Resolved).

2. System Modules & Functional Scope

🎓 Dual-Role Authentication System

Secure role-gated access with distinct views for Students/Callers (locked to Tactical SOS Portal & facility guides) and Administrators (full access to Command Center, ticket controls, and telemetry).

⚡ 1-Tap Zero-Delay Emergency Reporting

Rapid 1-tap preset triggers for Cardiac/Collapse, Severe Trauma/Bleeding, Active Fire/Smoke, and Physical Threat/Assault with instant dispatch and no manual typing required.

🧠 Heuristic Smart Triage Engine

Rule-based semantic parser categorizing incidents into Emergency, Urgent, and Normal. Generates medical justifications and bystander first-aid checklists.

📍 Campus Nearest Facilities Locator

Proximity engine mapping 25 campus locations to the closest Medical Dispensary, AED Defibrillator Hub, and First-Aid Kiosks/Eyewash Stations with real-time walking distances and ETAs.

5. Persistent Storage & Ticket Synchronization Model

All incident records are maintained in browser-backed persistent local storage (campus_triage_incidents_v2) with multi-tab storage event synchronization.

  • Instant Write-Through: Submissions and status transitions write to storage before UI update.
  • Reload Synchronization Actions: Users receive explicit "Reload Page to Update Ticket" controls and an optional 3-second auto-reload countdown to synchronize live database state.
  • Command Center Telemetry Reload: An administrative "Reload Telemetry" action in the dashboard header allows one-click data synchronization from persistent disk.
